# Звіти з оплати проїзду

Конструктор щотижневих звітів з оплати проїзду: співробітник вносить цифри тижня, а зведений звіт
(тиждень, місяць, рік) і PDF за зразком єДніпро формуються автоматично. React + Node.js (Express).

## Локальний запуск

```bash
npm install
npm run dev      # клієнт http://localhost:5173, API http://localhost:3001
npm test
```

PDF створює встановлений Chrome або Edge. Якщо їх не знайдено, вкажіть шлях у `BROWSER_PATH`.

## Правила розрахунку

- **Тиждень** — понеділок–неділя. Звіти нумеруються від першого (згори) до найновішого (внизу). Раніше за перший звіт створювати звіти не можна, перший звіт видалити не можна.
- **Рік** — календарний: сума тижнів року плюс «накопичене до цього тижня», яке вносять один раз у першому звіті.
- **Місяць** — календарний, накопичується з початку місяця. **Тиждень, що перетинає межу місяців, дає в новий місяць лише дні з 1-го числа**: наприклад, у звіті 26.10–01.11 місяць — це один день, 01.11. Ці дні не можна вивести з тижневих підсумків, тому для такого тижня місяць **вносять вручну**; поки поля порожні, місяць дорівнює 0.
- Місяць, внесений вручну, замінює розрахунок для рядка (це накопичене з початку місяця), а наступні тижні того ж місяця додаються до нього. Порожнє поле = автоматично.
- **Загальна кількість** розділу — без штрафів (вони в окремій таблиці), **загальна сума** — разом зі штрафами; кількість платежів = усі кількості, включно зі штрафами.

## Тарифи

Сума кожного рядка, включно зі штрафами, = кількість × ціна. Ціна штрафу за замовчуванням: **200 грн в електротранспорті і 360 грн в автобусах**; її, як і решту цін, можна змінити в звіті. Ціни підставляються за замовчуванням, їх можна змінити в кожному звіті; новий звіт успадковує ціни попереднього, а старі звіти не змінюються. Типові ціни лежать у `server/src/schema.js`.

## Змінні середовища

| Змінна | Призначення |
| --- | --- |
| `DATA_FILE` | Файл із даними (за замовчуванням `server/data/reports.json`). На хостингу — шлях на постійному томі, наприклад `/data/reports.json`. |
| `APP_PASSWORD` | Вмикає сторінку входу. Без неї застосунок відкритий усім. Після зміни пароля всі сесії завершуються. |
| `APP_USER` | Логін (за замовчуванням `admin`). |
| `SESSION_SECRET` | Необов'язково: окремий ключ підпису сесій (за замовчуванням виводиться з пароля). |
| `BROWSER_PATH` | Шлях до Chrome/Chromium для PDF. |
| `PORT` | Порт сервера (хостинг видає сам). |

## Railway

1. Створіть проєкт із цього GitHub-репозиторію. Railway збере `Dockerfile` (там уже є Chromium для PDF).
2. Додайте **Volume** і змонтуйте його в `/data`.
3. У змінних сервісу задайте `DATA_FILE=/data/reports.json`, `APP_PASSWORD` (свій пароль) і за потреби `APP_USER`.
4. Згенеруйте домен у Settings → Networking.
5. Перенесіть дані з комп'ютера (одноразово):

```bash
APP_PASSWORD=ваш-пароль node scripts/import-local-data.mjs https://ваш-домен.up.railway.app
```

Без тому дані зникають після кожного оновлення, бо файлова система контейнера тимчасова.
